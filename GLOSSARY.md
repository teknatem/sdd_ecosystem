# Наименования: SDD / Studio / Desktop / MPI

Канон имён экосистемы. Стек (Leptos, egui, Axum, Tauri) — в tech-доке, не в бренде.

> Переехал сюда 2026-08-18 из `sdd_studio/memory-bank/glossary/GLO__naming.md`.
> Studio — потребитель канона, а не его владелец.

## Три этажа

| Этаж | На экране | Аббр. | Расшифровка | Не говорить |
|---|---|---|---|---|
| Метод | Slice-Driven Design | **SDD** | Индексированный срез ведёт дизайн: тройка крейтов, роли, исполняемый каталог | VSA (как имя метода), ISA, Grid, Context-Driven |
| Инструмент | **SDD Studio** | — | Место работы над SDD-приложением | Designer, Builder, Dashboard, egui_designer_2, Code Grid |
| Инструмент | **SDD Desktop** | — | Десктоп-оболочка к SDD-приложению | mpi-desktop, клиент MPI |
| Продукт | **Integrator** | **MPI** | Marketplace Integrator — учёт и стыковка 1С с WB/Ozon/YM | Leptos Marketplace, leptos_marketplace_1 |

В речи: «MPI — SDD-приложение, открываю в Studio». «Studio» достаточно, если из
контекста ясно; в заголовке окна и README — **SDD Studio**.

DDD не переименовывается. DDD отвечает, *что* моделируем; SDD — *как это лежит*.

## Имена каталогов экосистемы

`F:\dev\<имя>`, все — члены одной экосистемы:

| Каталог | Что |
|---|---|
| `sdd_ecosystem` | канон (этот репозиторий) |
| `sdd_mpi_app` | приложение Integrator (MPI) |
| `sdd_studio` | анализатор |
| `sdd_desktop` | тонкий клиент |

Правило имени каталога:

- `sdd_` — префикс принадлежности экосистеме. Носят **все** каталоги, включая канон;
- `sdd_<код>_app` — приложение, построенное по методу. Суффикс `_app` отделяет его
  от инструментов, обслуживающих метод. Будущее второе приложение получает имя по
  той же форме;
- `sdd_<имя>` — инструмент экосистемы (`sdd_studio`, `sdd_desktop`);
- `sdd_ecosystem` — канон. Он не приложение и не инструмент, поэтому имя названо
  по тому, что внутри, а не по роли в работе.

До 2026-08-18 канон назывался просто `sdd` — на том основании, что приставка
означала «член экосистемы», а канон членом не является. Имя без префикса терялось
среди прочих `sdd*` и не читалось как «здесь лежат правила»; префикс теперь
означает принадлежность, а не роль.

Рабочие данные — не в репозитории, каталог называется **так же, как репозиторий**:
`F:\dev\sdd_mpi_app` ↔ `F:\data\sdd_mpi_app`. Одно имя в двух местах дешевле пары
«репо `sdd_mpi_app`, данные `mpi`», где приходится помнить соответствие.

## Поверхности имён

### SDD (метод)

| Поверхность | Канон | Сейчас |
|---|---|---|
| В речи и доке | SDD, Slice-Driven Design | местами VSA, «DDD+VSA» как синоним стандарта |
| Приложение по стандарту | SDD-приложение, SDD-проект | «leptos-проект», «VSA-проект» |
| Манифест правил | `architecture.toml` — **манифест SDD** | «конвенции», «проза architecture/» |
| Каталог объектов | `ARCHITECTURE.md` — **каталог SDD** | «карта проекта» |
| Глоссарий домена приложения | `CONTEXT.md` (это bounded context приложения, не имя метода) | — |
| Проверка правил | валидатор SDD (`check_architecture.ps1`) | «скрипт архитектуры» |
| Кэш/модель проекта | **`.sdd/`** | сделано (2026-08-18, было `.vsa_designer/`) |
| Override студии | `.sdd/config.json` | сделано (2026-08-18) |

Манифест — источник правды в репозитории приложения. Override студии — локальные
пороги и исключения, **не второй стандарт**. Не называть оба «конфигом архитектуры».

### SDD Studio

| Поверхность | Канон | Статус |
|---|---|---|
| Окно, README, продукт | SDD Studio | сделано |
| Крейт / exe | `sdd_studio` | сделано |
| Тип приложения | `StudioApp` | сделано |
| Настройки / persist | `sdd_studio.settings.json` / `sdd_studio.state.json` | сделано |

Внутри Studio слово **Designer** можно оставить за будущим режимом «проектируем
объект». Это не имя продукта.

Технические имена пайплайна (`stage1_analyze`, `stage2_tree_ui`,
`stage3_diagnostics`) переименовывать не обязательно; пользователю они показываются
как **Analyze**, **Tree**, **Diagnostics**.

Крейты `frontend` / `backend` / `contracts` **не переименовывать**: это origins, а
не бренд.

## Что уже названо правильно

Словарь самого метода — семейства индексов (`aNNN`, `p9NN`, `uNNN`, …), origins
B/C/F, статусы слоёв, роль, `common` — переименованию не подлежит и **здесь не
дублируется**: он объявлен в [SDD.md](SDD.md), а конкретный состав видов для
приложения — в его манифесте. Копия таблицы в глоссарии разошлась бы с оригиналом
первой же правкой.

Из имён, принадлежащих инструментам, правильно названы: Scene, LOD0/1/2, рёбра
`related` / `use` (модель сцены Studio) и имена артефактов анализа — они
перечислены в [CONTRACTS.md](CONTRACTS.md), стык №2.

## Что сознательно не брендируем

- DDD, CQRS, MVVM — чужие школы, свои имена.
- Leptos, egui, Axum, Thaw, Tauri — стек.
- `CONTEXT.md` — глоссарий домена приложения; не путать с Context-Driven Design.

## Роли и артефакты работы

| Роль | Имя |
|---|---|
| Кто сидит в Studio | разработчик (не «дизайнер», если речь не про UI) |
| Единица работы | объект SDD (срез с кодом) |
| Прогон анализа | analyze, не «билд» |
