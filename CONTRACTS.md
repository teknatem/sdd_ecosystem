# Контракты между репозиториями

Исчерпывающий список стыков экосистемы. Связь, которой здесь нет, — нарушение, а не
недокументированная фича. Появилась новая — сначала запись сюда, потом код.

Формат: у стыка есть **направление**, **носитель** (что физически пересекает
границу) и **что ломается при расхождении**. Третья графа — причина, по которой
контракт вообще записан: молчаливая поломка хуже громкой.

---

## 1. Манифест: приложение → Studio

**Носитель:** файл `architecture.toml` в корне приложения.
**Схема:** [MANIFEST_SCHEMA.md](MANIFEST_SCHEMA.md).

Studio читает манифест анализируемого проекта и судит структуру по нему, а не по
своим представлениям. Реализация — `sdd_studio/src/core/standard.rs`
(`STANDARD_FILE_NAME`), применение — `src/core/placement.rs`.

Правила стыка:

- **Отсутствие файла — не ошибка.** Проект без манифеста анализируется как раньше,
  на встроенных умолчаниях. Битый файл — ошибка: анализ по правилам, которых никто
  не писал, хуже отсутствия анализа.
- Манифест — собственность приложения. Studio его **только читает** и никогда не
  переписывает.
- Studio обязан уважать `[deviations]`. Иначе он производит findings на то, что
  приложение уже объявило осознанным, — и весь отчёт обесценивается.
- Приложение вправе завести раздел, которого Studio не понимает. Реакция Studio —
  игнорировать, а не падать.

**Ломается молча:** приложение добавило вид объекта в `[indices]`, Studio старой
версии его не знает и считает каталоги «безымянными». Метрика съезжает, ошибки нет.

## 2. Артефакты анализа: Studio → приложение

**Носитель:** каталог `.vsa_designer/` в корне приложения (**целевое имя — `.sdd/`**,
переименование ещё не сделано, см. ниже).

Studio пишет туда результат прогона; приложение забирает из него ровно одно число.

| Файл | Пишет | Читает |
|---|---|---|
| `diagnostics.json` | Studio | приложение → метрика findings анализатора |
| `scene_model.json` | Studio | Studio |
| `aggregate_metrics.json` | Studio | Studio |
| `project_files_index.csv` | Studio | Studio |

Правила стыка:

- Каталог **в `.gitignore` приложения**. На свежем клоне метрики просто нет — и это
  правильное поведение: «не измерено» и «найдено ноль» не должны выглядеть одинаково.
- Приложение читает только `diagnostics.json` и только поле `findings`. Остальные
  файлы — внутренняя кухня Studio, приложение в них не заглядывает.
- Отсутствие каталога приложение переживает без ошибки.

**Ломается молча:** переименование каталога или файла со стороны Studio. Приложение
не падает — оно перестаёт публиковать метрику, и никто этого не замечает.

**Незакрытый долг.** Имя `.vsa_designer` осталось от прежнего названия метода (VSA).
Целевое — `.sdd`. Переименование обязано быть **одним проходом по обоим репозиториям
сразу**: Studio пишет, приложение читает, порознь стык рвётся. Вместе с ним
переименовывается и ключ метрики, где ещё сидит `vsa`.

Адреса, чтобы у прохода не было поиска по репозиториям:

| Репо | Точка |
|---|---|
| `sdd_studio` | `src/core/model.rs` — константа `ARTIFACT_DIR`. Больше нигде имя не встречается |
| `sdd_mpi_app` | `.gitignore`; `tools/gen_code_metrics.ps1`; ключ `arch.vsa_findings` в `crates/backend/src/system/metrics/catalog.rs`; упоминание в `CLAUDE.md` |

Плюс существующие каталоги `.vsa_designer/` в рабочих копиях: они не под git, их
надо удалить руками, иначе рядом появится второй и метрика будет читаться из
старого.

## 3. Загрузка фронта: Desktop → приложение

**Носитель:** HTTP(S)-URL из профиля подключения. Кода репозитории не разделяют.

Самый слабый и потому самый здоровый стык: Desktop не знает о приложении ничего,
кроме адреса. Ни WASM, ни `crates/frontend`, ни `dist` в клиент не копируются —
переход на бандл-модель означал бы, что версия клиента должна совпадать с версией
сервера, а сейчас не должна.

Правила стыка:

- Главное окно грузит **удалённый** origin и не имеет ни одной Tauri-capability.
  У серверной страницы нет доступа к IPC. Это граница безопасности, а не настройка.
- IPC выдан только локальному окну профилей подключения.
- Приложение о существовании Desktop не знает и знать не должно: для него это
  обычный браузер.

**Ломается громко:** сервер недоступен — пользователь видит ошибку в окне
подключений. Приемлемо.

## Как заводить новый стык

1. Запись в этот файл: направление, носитель, что ломается молча.
2. Если носитель — файл или каталог, его имя фиксируется здесь и меняется только
   согласованным проходом по обоим репозиториям.
3. Если стык односторонний (один пишет, другой читает) — явно назвать владельца
   формата. У стыка без владельца формат разъезжается.
